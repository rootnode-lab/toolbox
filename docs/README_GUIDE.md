# README 작성 가이드

`toolbox`의 도구별 README를 작성하는 공통 기준입니다. 사용자가 도구 폴더를 전달받아 설치하고 실행하는 데 필요한 설명을 우선합니다.

## 문서별 역할

| 문서 | 역할 |
| --- | --- |
| [루트 README](../README.md) | 도구 목록, 저장소 소개와 공통 문서 안내 |
| 이 가이드 | 작성 규칙의 기준 문서 |
| [복사용 템플릿](templates/TOOL_README.md) | 새 도구에 복사할 문서 골격 |
| [PDF 변환 도구 README](../pdf-to-images/README.md) | 작성 규칙을 적용한 실제 예시 |

루트 README에는 각 도구의 상세 설치·실행 명령을 반복하지 않습니다.

## 1. 기본 구성

도구별 README는 다음 순서를 기본으로 합니다.

```text
도구 이름과 한 줄 설명
1. 최초 설치 — PC에서 한 번만
   1-1. 도구 폴더로 이동
   1-2. 실행 환경 만들기
   1-3. 필요한 라이브러리 설치
2. 도구 실행 — 사용할 때마다
   2-1. 도구 폴더로 이동
   2-2. 입력·출력 경로를 바꿔 실행
필요한 경우에만 확인
팀원에게 공유할 때
라이선스
```

설치가 필요 없는 도구는 해당 단계를 생략합니다. Python 이외의 도구도 실제 설치·실행 방식에 맞춰 조정합니다. 필요한 실행 환경은 최초 설치 설명 앞에 짧게 적습니다.

## 2. 단계와 명령어

- 상위 단계는 `## 1.`, `## 2.`로 표시합니다.
- 세부 단계는 `### 1-1.`, `### 1-2.`, `### 2-1.`처럼 소제목으로 표시합니다.
- 본문에서 단계를 참조할 때도 같은 번호를 사용합니다.
- 코드 블록 하나에 실행할 명령 한 줄만 넣습니다.
- “한 줄씩 입력하고 Enter를 누른 뒤, 명령이 끝나면 다음 단계로 이동”하도록 안내합니다.
- 그대로 입력할 명령과 경로를 바꿔야 하는 명령을 구분합니다.
- 사용자가 복사할 명령에는 터미널의 `PS C:\...>` 같은 프롬프트와 실행 결과를 넣지 않습니다.
- 실제 실행에 필요한 순서를 우선하고, 내부 구현 설명은 최소화합니다.

## 3. 경로와 결과 설명

- 개인 PC의 실제 사용자명이나 업무 경로 대신 `C:\tools\tool-name`, `C:\data\input.ext` 같은 예시를 사용합니다.
- 사용자가 바꿀 경로를 “입력 파일”, “결과를 저장할 폴더”로 구체적으로 설명합니다.
- 경로는 큰따옴표로 감싸고, 복사할 때 따옴표가 두 겹이 되지 않도록 안내합니다.
- 실행 직후 결과가 어디에 어떤 이름으로 생기는지 짧게 설명합니다.
- 원본 변경 여부와 기존 결과 덮어쓰기 여부는 실제 동작을 확인한 뒤 명시합니다.

## 4. 참고 표시

부가 설명은 인용 블록으로 구분합니다.

```markdown
> **참고:** 경로 양쪽의 큰따옴표는 하나씩만 유지하세요.
```

여러 항목은 하나의 참고 박스에 묶을 수 있습니다.

```markdown
> **참고**
>
> - 원본 파일을 수정하는지 안내합니다.
> - 같은 결과 파일이 있을 때의 동작을 안내합니다.
```

실행에 필수인 행동은 참고 박스에만 숨기지 않고 해당 단계의 본문에 적습니다.

## 5. 추가 옵션과 오류 해결

기본 사용에 필요하지 않은 옵션과 오류 해결은 `<details>`로 접어서 표시합니다. 요약에는 “추가 옵션”, “실행이 안 될 때”처럼 내용을 알 수 있는 제목을 씁니다.

- 옵션은 목적과 추가할 인수를 표로 정리합니다.
- 오류 설명은 “어떤 증상일 때 무엇을 할지”로 씁니다.
- 코드가 지원하는 옵션과 확인한 해결 방법만 적습니다.
- 기능이 없는 항목이나 불필요한 설치 단계를 양식에 맞추려고 추가하지 않습니다.

## 6. 공유와 라이선스

- 도구 폴더만 전달해도 사용할 수 있도록 코드, 설치 목록, README와 해당 도구의 라이선스를 함께 관리합니다.
- 가상환경, 개인 입력 파일과 생성 결과를 공유할 파일 목록에 섞지 않습니다.
- 라이선스는 도구별로 명시합니다. 다른 도구의 라이선스를 그대로 복사하지 않습니다.
- 외부 라이브러리의 조건과 직접 작성한 코드의 적용 범위를 구분합니다.
- 실제 존재하는 라이선스 파일과 문서만 링크로 연결합니다.

## 7. 새 도구에 적용하는 방법

1. [템플릿](templates/TOOL_README.md)을 새 도구 폴더의 `README.md`로 복사합니다.
2. 도구 이름, 실행 환경, 파일명과 예시 경로를 실제 사용법에 맞춥니다.
3. 필요 없는 단계와 옵션을 지우고, 작성자용 주석을 제거합니다.
4. 실행 명령, 결과 위치, 파일 변경 여부와 문서 링크를 확인합니다.
5. 루트 README의 도구 목록에 새 도구의 링크와 라이선스를 추가합니다.

규칙을 변경할 때는 이 가이드를 먼저 수정하고, 관련된 템플릿 항목을 맞춥니다. 기존 도구 문서는 해당 도구를 수정할 때 필요한 범위부터 적용합니다.
